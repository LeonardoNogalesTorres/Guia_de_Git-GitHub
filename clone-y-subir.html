Clonar y Flujo de Trabajo en Git

Aprende a clonar un repositorio y manejar el envío de cambios paso a paso (en 'main' y con ramas).

← Volver al Inicio

📌 Fase 1: Clonar y Preparar el Proyecto

Paso 1

Obtener la URL del Repositorio

Ve al proyecto en GitHub, haz clic en el botón verde Code y copia la URL que termina en .git (HTTPS).

Paso 2

Clonar el proyecto a tu equipo

Abre tu terminal en la carpeta donde quieras guardar el proyecto y ejecuta:

git clone https://github.com/usuario/nombre-del-proyecto.git # Descarga una copia completa del código e historial a tu máquina.
Paso 3

Entrar a la carpeta y abrir en VS Code

Usa la terminal para acceder al directorio del repositorio recién clonado:

cd nombre-del-proyecto # Entra a la carpeta del proyecto. code . # Abre el proyecto directamente en Visual Studio Code.

🟢 Variante A: Flujo Directo en 'main' (Flujo Simple)

Recomendado para proyectos individuales, tareas personales o entregas rápidas.

Paso A.1

Descargar cambios recientes (Pull)

Antes de empezar a escribir código, asegúrate de tener la versión más reciente del servidor:

git pull origin main # Trae e integra lo que esté subido en GitHub antes de trabajar.
Paso A.2

Guardar tus avances localmente

Realiza tus cambios en el código y guarda una instantánea localmente:

git status # Muestra los archivos que has creado o modificado. git add . # Prepara todos los archivos editados. git commit -m "Actualización del módulo de login" # Registra el estado de tus avances en el historial local.
Paso A.3

Subir los avances a GitHub

Envía tus confirmaciones locales hacia el repositorio remoto:

git push origin main # Publica tus cambios en la rama principal de GitHub.

🌿 Variante B: Flujo con Ramas Secundarias y Pull Request

Ideal para mantener el código principal intacto hasta revisar los cambios.

Paso B.1

Crear y cambiar a una nueva rama

Crea un espacio aislante para desarrollar tu nueva característica:

git switch -c feature/nueva-interfaz # Crea la rama 'feature/nueva-interfaz' y te traslada a ella.
Paso B.2

Guardar avances con Título y Descripción

Puedes estructurar el mensaje para que GitHub extraiga automáticamente el título y cuerpo del Pull Request usando doble -m:

git add . git commit -m "Se diseña la vista de inicio" -m "Descripción: Se incluyeron botones de navegación, hoja de estilos CSS y responsividad para móviles." # El primer -m será el Título del PR y el segundo -m la Descripción detallada.
Paso B.3

Subir la rama a GitHub

Publica tu rama en el servidor remoto:

git push -u origin feature/nueva-interfaz # Sube la rama y establece vinculación con origin.
Paso B.4

Crear el Pull Request (PR)

Tienes dos formas de abrir la solicitud de extracción para que el administrador la revise:

Opción 1: Desde la Web de GitHub (Recomendado)

  1. Entra al repositorio en GitHub. Verás un banner amarillo que dice "Compare & pull request". Haz clic en él.
  2. Escribe el Title (Título del cambio) y en el cuadro grande la Description (Explicación de lo que hiciste, pruebas realizadas o notas al administrador).
  3. Haz clic en el botón verde "Create pull request".

Opción 2: Desde la Terminal (GitHub CLI)

Si tienes instalada la herramienta gh (GitHub CLI), puedes hacer todo sin salir de la consola:

gh pr create --title "Se diseña la vista de inicio" --body "Se incluyeron botones de navegación y responsive design." # Crea el PR directamente asignando Título y Descripción por comandos.
Paso B.5

Fusionar (Merge) el Pull Request

Una vez revisados los cambios, el Pull Request se integra en la rama principal:

Desde la Web de GitHub

El administrador (o tú, si tienes permisos) presiona el botón verde "Merge pull request" y luego "Confirm merge".

Sincronizar cambios en tu computadora local

Tras hacer el Merge en GitHub, vuelve a tu terminal para actualizar tu rama main local:

git switch main # Regresas a la rama principal. git pull origin main # Descargas el código ya fusionado desde GitHub. git branch -d feature/nueva-interfaz # (Opcional) Borras la rama local que ya fue integrada.
