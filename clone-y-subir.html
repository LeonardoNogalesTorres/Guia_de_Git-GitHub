Clonar y Flujo de Trabajo en Git

Aprende a clonar un repositorio y manejar el envío de cambios paso a paso (en 'main' y con ramas).

← Volver al Inicio

📌 Fase 1: Clonar y Preparar el Proyecto

Paso 1

Obtener la URL del Repositorio

Ve al proyecto en GitHub, haz clic en el botón verde Code y copia la URL que termina en .git (HTTPS).

Paso 2

Clonar el proyecto a tu equipo

Abre tu terminal en la carpeta donde quieras guardar el proyecto y ejecuta:

git clone https://github.com/usuario/nombre-del-proyecto.git # Descarga una copia completa del código e historial a tu máquina.
Paso 3

Entrar a la carpeta y abrir en VS Code

Usa la terminal para acceder al directorio del repositorio recien clonado:

cd nombre-del-proyecto # Entra a la carpeta del proyecto. code . # Abre el proyecto directamente en Visual Studio Code.

🟢 Variante A: Flujo Directo en 'main' (Flujo Simple)

Recomendado para proyectos individuales, tareas personales o entregas rápidas.

Paso A.1

Descargar cambios recientes (Pull)

Antes de empezar a escribir código, asegúrate de tener la versión más reciente del servidor:

git pull origin main # Trae e integra lo que esté subido en GitHub antes de trabajar.
Paso A.2

Guardar tus avances localmente

Realiza tus cambios en el código y guarda una instantánea localmente:

git status # Muestra los archivos que has creado o modificado. git add . # Prepara todos los archivos editados. git commit -m "Actualización del módulo de login" # Registra el estado de tus avances en el historial local.
Paso A.3

Subir los avances a GitHub

Envía tus confirmaciones locales hacia el repositorio remoto:

git push origin main # Publica tus cambios en la rama principal de GitHub.

🌿 Variante B: Flujo con Ramas Secundarias (Trabajo Profesional / En Equipo)

Ideal para no tocar el código estable de main mientras desarrollas nuevas características.

Paso B.1

Crear y cambiar a una nueva rama

Crea un espacio de trabajo aislado para la funcionalidad en la que vas a trabajar:

git switch -c feature/nueva-interfaz # Crea la rama 'feature/nueva-interfaz' y te traslada a ella.
Paso B.2

Trabajar y guardar avances en la rama

Realiza los cambios necesarios en tu código. Los commits quedarán aislados en tu rama activa:

git add . git commit -m "Se diseña la estructura del menú"
Paso B.3

Subir la rama secundaria a GitHub

Sube la rama creada al servidor remoto para respaldarla o solicitar revisión:

git push -u origin feature/nueva-interfaz # Sube la rama por primera vez a GitHub y establece vinculación.
Paso B.4

Integrar (Merge) la rama a 'main'

Una vez terminada y probada la funcionalidad, fusiona la rama en main:

git switch main # Cambias a la rama principal. git pull origin main # Aseguras que tu rama principal esté al día. git merge feature/nueva-interfaz # Fusionas el código de tu rama secundaria dentro de main. git push origin main # Subes la rama main actualizada a GitHub.
